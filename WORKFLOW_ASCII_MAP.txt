╔══════════════════════════════════════════════════════════════════════════════╗
║                   4️⃣  HELPDESK - TICKET MANAGEMENT                          ║
╠══════════════════════════════════════════════════════════════════════════════╣
║                                                                              ║
║  Complete Ticket Lifecycle:                                                 ║
║                                                                              ║
║         ┌─────────────────────────────────────────────────────┐             ║
║         │  🟢 OPEN → 🟡 WAITING → 🔵 RESOLVED → ⚫ CLOSED    │             ║
║         └─────────────────────────────────────────────────────┘             ║
║                                                                              ║
║  🤖 Auto-Assignment Engine:                                                 ║
║  • Score-based: Workload(40%) + Skill(30%) + Online Status(30%)            ║
║  • Redis-locked per org (prevents double-assignment)                        ║
║  • Best agent = lowest score = highest priority                             ║
║                                                                              ║
║  ⏸️  SLA Pause Logic:                                                        ║
║  • Status "WAITING" → Pauses SLA countdown                                  ║
║  • Accumulates pause time → Recalculates deadline                           ║
║  • Fair SLA: Time waiting on customer doesn't count                         ║
║                                                                              ║
║  📊 SLA Monitoring (every 5 min):                                            ║
║  • Read priority-based policy (response/resolution hours)                   ║
║  • Calculate deadline with pause logic                                      ║
║  • 2h before breach: Notify agent                                           ║
║  • At breach: Notify admin + log event                                      ║
║                                                                              ║
║  Endpoints: GET/POST /tickets, PUT /tickets/{id}, POST /tickets/{id}/replies║
║  Tables: tickets, ticket_replies, ticket_activities, ticket_attachments    ║
║                                                                              ║

╔══════════════════════════════════════════════════════════════════════════════╗
║                   5️⃣  EMAIL INTEGRATION                                     ║
╠══════════════════════════════════════════════════════════════════════════════╣
║                                                                              ║
║  Inbound (IMAP Polling - every 5 min):                                       ║
║                                                                              ║
║  IMAP Fetch → Parse Headers → Check Threading → Create/Reply               ║
║                           ↓                                                  ║
║  In-Reply-To: Maps to existing ticket                                        ║
║  New Subject: Creates new ticket                                             ║
║  Auto-Reopen: If customer replies to closed ticket                           ║
║                                                                              ║
║  Outbound (Email Outbox Pattern):                                            ║
║                                                                              ║
║  Agent Sends Reply → Queue in email_outbox → Celery drain (5 min)           ║
║                           ↓                                                  ║
║  Exponential Backoff Retry (60s, 300s, 900s, 1800s, 3600s)                 ║
║  Max 5 attempts → Mark sent/failed                                           ║
║  Guarantee: No email lost on app crash                                       ║
║                                                                              ║
║  Email Threading:                                                           ║
║  • Message-ID → email_threads table                                         ║
║  • In-Reply-To → Links to previous message                                 ║
║  • Full conversation preserved                                              ║
║                                                                              ║
║  Tables: email_log, email_threads, email_outbox                             ║
║                                                                              ║

║                   1️⃣2️⃣ COMPLIANCE & SECURITY                                ║
╠══════════════════════════════════════════════════════════════════════════════╣
║                                                                              ║
║  Role-Based Access Control (RBAC):                                           ║
║  Admin   → Platform-wide access                                              ║
║  Staff   → Assigned orgs only (via staff_org_assignments)                   ║
║  Customer → Own org only (org_id == user.org_id)                            ║
║                                                                              ║
║  Org-Level Scoping:                                                         ║
║  Every query filtered by org_id using org_scope_filter()                    ║
║  Example: SELECT * FROM tickets WHERE org_id = ?                            ║
║           (org_id bound to current_user.org_id)                             ║
║                                                                              ║
║  Token Rotation & Reuse Detection:                                           ║
║  Old token: refresh_token_v1                                                 ║
║  New token: refresh_token_v2 (revoke old)                                   ║
║  Replay v1: Detected! → Revoke ALL sessions (theft assumed)                 ║
║                                                                              ║
║  Password Security:                                                         ║
║  Bcrypt with 12 rounds → Resist GPU cracking                                ║
║  Never returned in API responses                                             ║
║                                                                              ║
║  Audit Logging:                                                             ║
║  • login_history: All login attempts (success/fail)                         ║
║  • ticket_activities: All status changes                                    ║
║  • IP & User-Agent tracking                                                 ║
║                                                                              ║
║  Data Validation:                                                           ║
║  • Pydantic schemas (type checking, length limits)                          ║
║  • Magic bytes (file content verification)                                  ║
║  • SQLAlchemy ORM (SQL injection prevention)                                ║
║                                                                              ║
